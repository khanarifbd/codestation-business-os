# Capital additive exact-decimal HTTP contract

Capital and Capital Insights keep every existing response field and its previous JSON type/value. Financial Decimal fields additionally expose a sibling `<field>_exact`: a fixed-point decimal string preserving the original Decimal scale and sign. Optional null financial fields expose null companions. Counts, IDs, status and date fields have no companions. The complete 41-field mapping is documented by the OpenAPI `CapitalExactResponse` component's `x-capital-exact-decimal-fields` and `x-capital-exact-companions` extensions and in `app/schemas/capital_response.py`.

Example: original `committed_amount: 90071992547409.9` remains for compatibility; `committed_amount_exact: "90071992547409.91"` preserves the source cents. Consumers doing monetary display or arithmetic should validate and prefer the exact companion. Legacy numeric fields retain their historical floating-point limitation; they cannot restore already-lost precision. Null `valuation_amount` has null `valuation_amount_exact`. Percentages/share values retain their four-decimal source scale, rather than being rounded to money precision.

All 22 Capital routes and the Insights route serialize through this boundary. Endpoint names, permissions, status codes, accounting arithmetic/posting and database schemas are unchanged. Direct Python handler calls still return native Decimal objects, preserving existing verification and internal accounting callers. Only HTTP response serialization adds the companions; no query flag is required and no global serializer is installed.

`tests/test_capital_exact_response_unit.py` runs actual FastAPI TestClient GET and POST with synthetic in-memory DB collaborators (no real DB/network), validates all23 route serialization/OpenAPI registrations, 18,2 extremes, nested fields/nulls/rates, original-field value/type/JSON-byte parity after removing companions, direct handler Decimal types and unchanged complete handler source bodies. It runs fail-closed at the beginning of the existing CI `scripts/verify_capital.py` entry, before the unchanged ledger fixture verification. This does not replace the PostgreSQL ledger or actual browser tests.
